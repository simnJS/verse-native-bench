Verse natives vs rewrites

Approach

The question: for each native function Fortnite gives to Verse code (vector math, standard library, arrays, sorting), is a hand-written Verse version faster, and does the answer hold on the VM that actually runs islands?

  1. Real runtimes, outside the game. From Unreal Engine's public source, we built Epic's own Verse command-line runners for both backends: VerseCmd on the new VerseVM, and VerseCLR on the BPVM, the Blueprint VM that Fortnite runs today (in Development and Shipping builds). Both include the real native implementations of /UnrealEngine.com/Temporary/SpatialMath and /Verse.org/SpatialMath, and print each profile block's duration.
  2. Rewrites that stay drop-in. Every rewrite is plain Verse that can be pasted into a UEFN project, with the same signature and failure behaviour as the native it replaces.
  3. Same result, checked bit for bit. Before any timing, each rewrite is compared with its native over thousands of inputs, edge cases included (NaN, infinities, subnormals, signed zeros, failing <decides> calls). All 96 check groups show no divergence on every runtime; only Sqrt and the transcendental functions differ, by 1 to 3 units in the last place.
  4. Timing. Each benchmark times the native and the rewrite on the same prebuilt inputs, in separate profile blocks. The suite runs 4 times; the first round is a warm-up and the table uses the median.
  5. Confirmation in a UEFN session. The same files run in a UEFN play session on an Epic server. The suite is split into short steps with a Sleep(0.0) between them, since UEFN stops code that runs for about 10 seconds without suspending. The final checksum matches the local runs exactly.

What it shows

Struct construction is the cost

On the BPVM, each vector3{} of /UnrealEngine.com/Temporary/SpatialMath allocates three strings and a map before setting its fields. Rewrites that avoid intermediate vectors win 3 to 15×.

Representation beats rewriting

The same vector math on tuples is 15 to 18× faster in UEFN; the /Verse.org/SpatialMath vector3, backed by a C++ struct, is about 13× faster.

C++ natives stay faster

Sqrt, trigonometry, Exp/Ln, rounding and Abs are 2 to 40× slower when rewritten. Keep the natives.

UEFN agrees with the local BPVM

No function matches these filters.

Reading the table

Speed-up = native time ÷ rewrite time, on the median of the timed rounds. Above 1×, the rewrite is faster. Each cell also shows both times in milliseconds; absolute times depend on the machine, so compare ratios within one VM.

"Tuple" and "VerseOrg" rows compare representations (a (float, float, float) tuple, and the /Verse.org/SpatialMath vector3) with the /UnrealEngine.com/Temporary/SpatialMath vector3. "Scalar" computes on floats and builds a single vector at the end. "Inlined" is a sort specialised for floats; "Fast" is a drop-in rewrite.

Local builds come from an earlier Unreal Engine revision than Fortnite's, and the UEFN server is about 1.8× slower than the local Shipping build. Easing is an experimental API: using it blocks publishing an island.
